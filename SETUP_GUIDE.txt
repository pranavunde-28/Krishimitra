================================================================================
                    KRISHIMITRA - LOCAL SETUP GUIDE
================================================================================

This guide will help you set up and run KrishiMitra webapp locally on any machine.

================================================================================
PREREQUISITES (Install These First)
================================================================================

1. Node.js (v18 or higher)
   - Download: https://nodejs.org/
   - Install the LTS (Long Term Support) version
   - Verify installation: Open terminal/cmd and run:
     node --version
     npm --version

2. Git
   - Download: https://git-scm.com/
   - Verify installation:
     git --version

3. Code Editor (Optional but recommended)
   - VS Code: https://code.visualstudio.com/

================================================================================
STEP 1: CLONE THE REPOSITORY
================================================================================

Open terminal/command prompt and run:

git clone https://github.com/DurgeshKayastha/krishimitra.git
cd krishimitra

================================================================================
STEP 2: BACKEND SETUP
================================================================================

1. Navigate to backend folder:
   cd backend

2. Install dependencies:
   npm install

3. Create a file named ".env" in the backend folder with this content:

GROQ_API_KEY=your_groq_api_key_here
DATA_GOV_IN_API_KEY=your_data_gov_api_key_here
CROP_HEALTH_API_KEY=your_crop_health_api_key_here
FIREBASE_SERVICE_ACCOUNT_KEY_PATH=./serviceAccountKey.json
PORT=5000

4. Optional: Download a Firebase Service Account Key only if you specifically use a backend Firebase Admin route:
   - Go to Firebase Console: https://console.firebase.google.com/
   - Select your project
   - Go to Project Settings > Service Accounts
   - Click "Generate New Private Key"
   - Save the downloaded JSON file as "serviceAccountKey.json"
   - Place it in the backend folder; never put it in frontend/.env or commit it

================================================================================
STEP 3: FRONTEND SETUP
================================================================================

1. Navigate to the frontend folder from the project root:
   cd frontend

2. Install dependencies:
   npm install

3. In the frontend folder, copy .env.example to .env. Replace every placeholder with the exact Web app config values shown in Firebase Console > Project settings > General > Your apps. Do not use the example values literally. Restart Vite after editing .env.

================================================================================
STEP 4: OBTAIN API KEYS
================================================================================

You need to get API keys from these services:

1. GROQ API KEY
   - Website: https://console.groq.com/
   - Sign up for free account
   - Go to API Keys section
   - Create new API key
   - Copy and paste in backend .env file

2. DATA.GOV.IN API KEY
   - Website: https://data.gov.in/
   - Register for account
   - Go to your profile/API section
   - Request API access
   - Copy API key to backend .env file

3. CROP HEALTH API KEY
   - Website: https://crop.health/
   - Sign up for developer account
   - Get API key from dashboard
   - Copy to backend .env file

4. FIREBASE CONFIGURATION
   - Website: https://console.firebase.google.com/
   - Create new project or use existing
   - Go to Project Settings
   - Scroll to "Your apps" section
   - Click web app icon (</>)
   - Copy all the Web app config values to frontend/.env
   - Create Firestore and enable Authentication as described below
   - A service-account key is not needed for the frontend app

5. GOOGLE MAPS API KEY
   - Website: https://console.cloud.google.com/
   - Create new project or select existing
   - Enable "Maps JavaScript API"
   - Go to Credentials
   - Create API key
   - Copy to frontend .env file

================================================================================
FIRESTORE AND AUTHENTICATION SETUP (REQUIRED FOR COMMUNITY + ALERTS)
================================================================================

1. In Firebase Console (https://console.firebase.google.com/), create or select
   ONE project. Use this same project for every developer machine and deployed
   version that should share community messages and disease reports.

2. Open Build > Firestore Database and click "Create database". Choose Native
   mode and select a region near your users (for example, asia-south1 for Mumbai).
   The database location cannot be changed after creation. Do not create
   collections manually; Firestore creates posts, comments, and diseaseReports
   when the app writes its first records.

3. Open Build > Authentication > Sign-in method and enable Google. The app also
   offers phone sign-in; enable Phone only if you have configured its SMS/billing
   requirements. Under Authentication > Settings > Authorized domains, ensure
   localhost and your deployed website domain are listed.

4. In Project settings > General > Your apps, register a Web app (</>) if needed.
   Copy its config into frontend/.env, copied from frontend/.env.example. Confirm
   VITE_FIREBASE_PROJECT_ID exactly matches the selected Firebase project ID.
   Restart the frontend dev server after changing .env.

5. Deploy this repository's Firestore rules from the project root. Install the
   Firebase CLI if needed, then run:

   npm install -g firebase-tools
   firebase login
   firebase use --add
   firebase deploy --only firestore:rules

   When prompted, choose the SAME project ID used in frontend/.env. Alternatively,
   open Firestore Database > Rules in Firebase Console, paste the contents of
   firestore.rules, and click Publish. Never use open/test-mode rules for a
   deployed app.

6. Sign in to KrishiMitra, create a Community post, and submit a disease report.
   Check Firebase Console > Firestore Database > Data for:
   - posts/{postId}
   - posts/{postId}/comments/{commentId}
   - diseaseReports/{reportId}
   - users/{Firebase Auth UID}

   Sign in on another browser/device configured with the same project ID.
   Community and Alerts subscribe to Firestore in real time. If clients use
   different project IDs, they use separate databases and cannot see one
   another's records. Changing projects does not copy previous data.

7. To make an account an officer, a Firebase project administrator must set
   users/{Firebase Auth UID}.role to "officer" in Firestore Console. The rules
   prevent users from assigning themselves this role.

IMPORTANT: These rules allow any signed-in user to read Community posts and
disease reports. Disease reports include the reporter's name and precise GPS
location. Obtain consent before submitting or sharing location data.

Community posts and disease reports are written directly from the frontend, so
they do NOT require a backend service-account key. Never put a service-account
JSON key in frontend/.env or commit it to source control.

================================================================================
STEP 5: RUN THE APPLICATION
================================================================================

You need to run BOTH backend and frontend in SEPARATE terminal windows:

TERMINAL 1 - Start Backend Server:
----------------------------------
cd backend
npm run dev

You should see: "Server on port 5000"
Backend URL: http://localhost:5000


TERMINAL 2 - Start Frontend Server:
-----------------------------------
cd frontend
npm run dev

You should see: "Local: http://localhost:5173"
Frontend URL: http://localhost:5173

Now open your browser and go to: http://localhost:5173

================================================================================
TROUBLESHOOTING
================================================================================

Problem: "npm: command not found"
Solution: Node.js is not installed or not in PATH. Reinstall Node.js.

Problem: "Port 5000 already in use"
Solution: Change PORT in backend .env to 5001, and update VITE_BACKEND_URL 
          in frontend .env to http://localhost:5001

Problem: "Module not found" errors
Solution: Delete node_modules folder and package-lock.json, then run npm install again

Problem: Firebase errors
Solution: Check frontend/.env, confirm its project ID, enable Google sign-in, create Firestore, and deploy firestore.rules. The Community page shows a specific message if configuration or Firestore permissions are wrong.

Problem: API errors (429, 401)
Solution: Check if all API keys are correctly added in .env files

Problem: CORS errors
Solution: Make sure backend is running and VITE_BACKEND_URL is correct

================================================================================
IMPORTANT NOTES
================================================================================

1. NEVER commit .env files or serviceAccountKey.json to GitHub
2. Keep your API keys secret and secure
3. Free tier API limits:
   - Groq: Generous free tier
   - Data.gov.in: Limited requests per day
   - Crop Health: 100 identifications/month
   - Firebase: 50K reads, 20K writes per day

4. Both backend and frontend must be running simultaneously
5. Backend runs on port 5000, frontend on port 5173
6. Always check console for errors if something doesn't work
